## Лабораторная работа №5: Построение AST и проверка контекстно-зависимых условий
**Цель работы:** Изучить назначение и принципы работы семантического анализатора в структуре компилятора. Освоить методы построения абстрактного синтаксического дерева (AST) и проверки контекстно-зависимых условий (семантических правил) для заданной синтаксической конструкции.

**Постановка задачи:** Развить ранее созданный синтаксический анализатор (парсер) до семантического: построить абстрактное синтаксическое дерево (AST) и реализовать проверку контекстно-зависимых условий в соответствии с индивидуальным вариантом курсовой работы.

**Вариант задания №3 Объявление комплексного числа с инициализацией на языке Python**

Примеры коректных входных строк:

1. Базовое объявление

```z3 = complex(0, 2.5);```

2. Разные имена и значения

```complex_num_1 = complex(10, 3.14159);```

3. Многострочный код с несколькими объявлениями

```
z1 = complex(0, 1.5);
z2 = complex(2, 3.0);
z3 = complex(4, 5.75);
```

**Контекстно-зависимые условия**

1.Проверка уникальности имён

Каждый идентификатор может быть объявлен только один раз. Если имя уже находится в таблице символов, повторное объявление считается семантической ошибкой.

Пример ошибки — повтор элемента перечисления:

```
z1 = complex(1, 2.3);
z1 = complex(4, 5);
```

Ожидаемое сообщение:

```Ошибка: идентификатор "z1" уже объявлен ранее```

Данная проверка реализуется с помощью таблицы символов. При обработке нового имени анализатор пытается добавить его в таблицу. Если имя уже существует, формируется семантическая ошибка.

2.Проверка совместимости типов

Пример ошибки — логическое значение в списке enum:

```z1 = complex("abc", true);```

Ожидаемые сообщения:

```
Ошибка: строковое значение не может использоваться как числовой аргумент функции complex
Ошибка: логическое значение не может использоваться как числовой аргумент функции complex
```

Значения "abc" и true синтаксически могут быть распознаны как отдельные литералы, однако по смыслу они не подходят для формирования комплексного числа. Поэтому ошибка фиксируется именно на этапе семантического анализа.

3.Проверка допустимых значений

Для числовых литералов выполняется проверка диапазона. Целые значения должны помещаться в допустимый диапазон.

Пример ошибки — пустой список элементов:

```z1 = complex(999999999999999999999, 2.3);```

Ожидаемое сообщение:

```Ошибка: целый литерал выходит за пределы диапазона.```

4.Проверка использования объявленных идентификаторов

Если в качестве аргумента complex(...) используется идентификатор, он должен быть объявлен ранее.

Некорректный пример

```z2 = complex(z1, 0);```

Ожидаемое сообщение

```Ошибка: идентификатор "z1" использован до объявления или не объявлен```

**Структура AST**

В программе используются следующие основные типы узлов.

ProgramNode — корневой узел AST.

Он представляет всю анализируемую программу или весь введённый фрагмент текста.

Содержит список операторов объявления комплексных чисел.

ComplexDeclNode — узел объявления комплексного числа.

Соответствует конструкции:

z1 = complex(1, 2.3);

LiteralNode — узел числового, строкового или логического литерала.

В корректных строках внутри complex(...) используются числовые литералы.

IdentifierRefNode — узел ссылки на ранее объявленный идентификатор.

Используется, если аргументом функции complex(...) является имя переменной.
